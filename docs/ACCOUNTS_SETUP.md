# Акаунти VARTA UA — налаштування

Це основа API акаунтів, **без підключеної бази вона навмисно не працює**. Карта і графіки світла залишаються доступними незалежно.

## Render Environment Variables (не комітити значення)
- `DATABASE_URL`: URL **постійної зовнішньої PostgreSQL** бази (`postgresql://...`). Можна використати безкоштовний тариф провайдера, якщо він є і ліміти підходять.
- `TELEGRAM_BOT_TOKEN`: секретний токен Telegram-бота для перевірки `initData`.
- `SESSION_SECRET`: випадковий криптографічний секрет щонайменше 32 символи, наприклад з `python -c "import secrets; print(secrets.token_urlsafe(48))"`.
- `ALERTS_IN_UA_TOKEN`: як раніше, для карти тривог.

Після налаштування й деплою API:
- `POST /api/account/telegram` JSON `{"init_data":"<Telegram.WebApp.initData>"}` — вхід/створення профілю.
- `GET /api/account/me` — заголовок `Authorization: Bearer <access_token>`.
- `PATCH /api/account/me` — зміна власного ніка, міста, черги, тем та сповіщень.
- `DELETE /api/account/me` — видалення профілю та його налаштувань.

Токен доступу чинний 24 години. **Нік не дорівнює Telegram username.** Аватар за замовчуванням відсутній; завантаження фотографій і платні аватари ще не реалізовані.

## Обмеження та наступні кроки
- Підключити фронтенд Telegram Mini App до API, зберігати токен обережно, не передавати його в URL.
- Додати міграції Alembic перед змінами схеми в production; зараз таблиці створюються на старті.
- Увімкнути резервні копії БД і протестувати відновлення.
- Перед відкритим запуском додати rate limiting на логін та редагування профілю, аудит доступу, правила конфіденційності.
- Видалення акаунта наразі стосується лише двох таблиць. Майбутні чати, платежі та медіафайли мають мати окрему політику видалення.
- Безкоштовні тарифи та можливість працювати без витрат потрібно перевіряти перед розгортанням. Не використовувати локальну SQLite на ефемерному Render.
